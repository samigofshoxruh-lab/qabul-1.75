# Qabul: CRM-бот на Supabase

Клиент пишет в соцсеть, бот задаёт ваши вопросы, анкета и переписка появляются на сайте, администратор берёт заявку в работу и отвечает прямо оттуда.

Главный админ создаёт компании и пользователей и задаёт им срок доступа. Регистрации нет: вход только по выданному логину.

Каналы: Telegram (бот и личный аккаунт через Telegram Business), Instagram, Facebook Messenger, WhatsApp Cloud API, Viber, ВКонтакте.

## Что нужно заранее

Node.js 20+ и проект на [supabase.com](https://supabase.com). Supabase CLI ставить не нужно, он запускается через `npx`.

## Установка

Из папки проекта. В Windows используйте Командную строку (cmd), а не PowerShell: там `npx` часто заблокирован настройками безопасности.

```bash
npm install
npx supabase login
npx supabase link --project-ref ВАШ_PROJECT_REF   # Project Settings → General
npx supabase db push --remote                     # таблицы, RLS, логика бота
```

Секреты для Edge Functions. Подойдут любые случайные строки от 32 символов:

```bash
npx supabase secrets set TOKEN_ENCRYPTION_KEY=... CRON_SECRET=...
```

`TOKEN_ENCRYPTION_KEY` шифрует токены соцсетей. Если его сменить или потерять, каналы придётся подключить заново.

Функции (флаг `--use-api` позволяет обойтись без Docker):

```bash
npx supabase functions deploy --use-api
```

Настройки входа и закрытие регистрации уже описаны в `supabase/config.toml`. Укажите там в `site_url` адрес своего сайта и примените:

```bash
npx supabase config push
```

### Главный админ

Создайте пользователя в панели Supabase (Authentication → Users → Add user) и назначьте его главным админом в SQL Editor:

```sql
insert into public.platform_admins (user_id)
select id from auth.users where email = 'ВАШ_EMAIL';
```

Этот email намеренно не записан в коде: репозиторий открытый. После входа главный админ видит раздел «Компании».

### Сайт на компьютере

```bash
copy .env.example .env   # Linux и macOS: cp. Внутри адрес проекта и publishable key
npm run dev              # http://localhost:5173, в Windows можно дважды нажать start-site.cmd
```

### Сайт в интернете: GitHub Pages

Файл `.github/workflows/deploy.yml` собирает и публикует сайт при каждом push в `main`.

1. В настройках репозитория Settings → Pages выберите Source: GitHub Actions.
2. В Settings → Secrets and variables → Actions → Variables добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`.
3. Сделайте push в `main`. Адрес сайта появится в Settings → Pages.

**Свой домен:** укажите его в Settings → Pages → Custom domain, добавьте DNS-записи по подсказке GitHub и замените `site_url` в `supabase/config.toml`. Менять код не нужно.

Бесплатный GitHub Pages работает только с открытым репозиторием. Токены и пароли в код не попадают: они лежат в Supabase, а publishable key по своему назначению виден в браузере.

### Расписание

Расписание включает миграция: раз в час проверяются каналы и продлеваются токены Instagram, каждые 5 минут уходят напоминания об уроках, раз в час проверяются сроки компаний. Функциям нужны два значения в Supabase Vault и секрет `CRON_SECRET`, в коде их нет:

```sql
select vault.create_secret('https://ВАШ_ПРОЕКТ.supabase.co/functions/v1', 'qabul_functions_url');
select vault.create_secret('СЛУЧАЙНАЯ_СТРОКА', 'qabul_cron_secret');
```

Ту же строку задайте командой `npx supabase secrets set CRON_SECRET=СЛУЧАЙНАЯ_СТРОКА`.

## Как подключить каналы

Начните с Telegram: там всё заработает за минуту и можно проверить весь путь от сообщения до заявки. Инструкции для каждой соцсети есть в окне подключения на сайте.

| Канал | Что вставить | Что ещё нужно |
| --- | --- | --- |
| Telegram | Токен от @BotFather | Ничего |
| Telegram, личный аккаунт | Тот же токен | Business Mode в @BotFather, затем Настройки → Telegram для бизнеса → Чат-боты |
| ВКонтакте | Ключ сообщества с правами «Управление» и «Сообщения» | Включённые сообщения в сообществе |
| Viber | Токен бота | Бот создаётся только на коммерческих условиях Viber, с абонентской платой |
| Instagram | Access token, Instagram App Secret | Приложение Meta, Webhooks, режим Live, App Review |
| Facebook | Page access token, App Secret | Приложение Meta, Webhooks, режим Live, App Review |
| WhatsApp | Токен System User, Phone number ID, WABA ID, App Secret | Приложение Meta, Webhooks, режим Live |

### Важно про Instagram и Facebook

Одного токена здесь мало, это требование Meta:

1. На developers.facebook.com создаётся приложение, а Callback URL и Verify token вставляются в раздел Webhooks. Сайт покажет оба значения после подключения.
2. По документации Meta приложение со Standard Access общается только с людьми, у которых есть роль в приложении. Обычные клиенты начнут доходить до бота после режима Live и получения Advanced Access на `instagram_business_manage_messages` (для Facebook на `pages_messaging`) через App Review и Business Verification.
3. Для App Review понадобятся страница с политикой конфиденциальности и инструкция по удалению данных. Требование о передаче диалога человеку уже выполнено: клиент может написать «оператор», а администратор отвечает с сайта.

Для проверки добавьте свой второй аккаунт как Instagram Tester в разделе App Roles.

## Как ведёт себя бот

- Первое сообщение клиента любого содержания запускает опрос: приветствие и первый вопрос.
- Кнопки приходят там, где платформа их поддерживает. Клиент также может ответить текстом варианта или его номером.
- Подпись длиннее лимита кнопки (в Instagram и Facebook это 20 символов) уходит нумерованным списком, а на кнопках остаются цифры.
- Неверный ответ получает подсказку. После трёх ошибок подряд или слова «оператор», «менеджер», «человек» заявка передаётся администратору.
- Когда администратор взял заявку или ответил клиенту, бот замолкает. В Telegram Business то же происходит, если владелец написал клиенту сам.
- После завершения опроса новые сообщения клиента просто попадают в заявку.
- Сообщение в течение 24 часов после закрытия заявки открывает её снова. Позже начинается новый опрос. Срок задаётся полем `restart_after_hours` в таблице `surveys`.
- Группы и беседы бот игнорирует.

## Что есть на сайте

- **Компании** (главный админ): создание компаний и пользователей, срок на месяцы или до даты, бессрочный доступ, приостановка, личный срок и смена пароля пользователя, полное удаление компании со всеми данными.
- **Заявки**: статусы, анкета, переписка, ответ клиенту, заметка, запись на урок, поиск, выгрузка в CSV для Excel.
- **Уроки**: название, время, длительность, свободные заметки, ученики из заявок и вручную, заметка по каждому ученику.
- **Вопросы**: несколько опросов, три типа ответа (выбор, текст, телефон), свой вариант, необязательные вопросы, порядок, просмотр глазами клиента.
- **Каналы**: подключение, проверка, замена токена, выбор опроса для канала, пауза.
- **Команда**: администраторы видят заявки и уроки и отвечают клиентам, вопросы и каналы меняет только владелец.
- **Посещаемость и оплаты**: в уроке отмечается, кто пришёл, сколько должен заплатить и сколько заплатил. Раздел «Оплаты» показывает долги по всем урокам; будущие уроки считаются отдельно и в долг не входят.
- **Напоминания об уроке**: бот пишет ученикам из заявок за день и за час до урока, результат виден в уроке. Ученику, добавленному вручную, писать некуда. Instagram, Facebook и WhatsApp пропускают сообщение, только если клиент писал за последние 24 часа. Ответ на напоминание попадает к администратору, опрос заново не начинается.
- **Быстрые ответы**: кнопки над полем ответа вставляют готовый текст, перед отправкой его можно поправить.
- **Предупреждения владельцу**: за 7, 3 и 1 день до конца срока приходит сообщение в «Поддержку Qabul». Если токен канала перестал работать, предупреждение видно на всех страницах сайта. Токены Instagram продлеваются сами.
- **Instagram, два вида токенов**: токен Business Login for Instagram (начинается с IG, живёт 60 дней и продлевается сам) и токен Facebook Login или Unified login (начинается с EAA, не истекает). Для EAA-токена сайт сам находит аккаунт Instagram через `me/assigned_instagram_accounts`, затем страницу или список страниц, и пишет через `graph.facebook.com/{ig-id}/messages`. App Secret в этом случае берётся из App settings → Basic.
- **Личный срок и продление**: продление компании снимает личный срок владельца, поэтому владелец всегда живёт по сроку компании. Личные сроки сотрудников остаются, сайт предупреждает, если они заканчиваются раньше срока компании, и снимает их одной кнопкой.
- **Поддержка Qabul**: переписка владельца компании с главным админом, запрос продления, работает и при истёкшем сроке. Главный админ продлевает доступ прямо из переписки.

Когда срок компании закончился, её пользователи видят сообщение вместо кабинета, а бот перестаёт отвечать клиентам. Сообщения клиентов за это время не сохраняются. Данные остаются, и после продления всё работает как раньше.

## Устройство

```
supabase/migrations/      схема, RLS, логика опроса (bot_handle_inbound)
supabase/functions/
  webhook/                приём сообщений и проверка подписей
  channels/               подключение каналов, шифрование токенов
  send-message/           ответ администратора
  team/                   администраторы компании
  platform/               консоль главного админа
  refresh-tokens/         продление токенов Instagram и проверка каналов
  reminders/              напоминания ученикам об уроке
  _shared/adapters/       по файлу на соцсеть
src/                      сайт на React
tests/                    тесты
```

Опрос обрабатывается внутри Postgres одной транзакцией на сообщение. Поэтому повторная доставка webhook и несколько сообщений подряд не создают дублей и не сбивают порядок вопросов.

Токены шифруются AES-GCM в Edge Function и лежат в `channel_secrets`, куда у браузера нет доступа.

**Новая соцсеть**: файл в `_shared/adapters/` с реализацией интерфейса `Adapter`, строка в `adapters/index.ts`, разбор входящих в `webhook/index.ts`, значение в ограничении `channels.platform` и описание в `src/lib/platforms.ts`.

## Ограничения

- Instagram и Facebook не сообщают, что вы ответили прямо в их приложении, поэтому такие ответы не попадают в переписку на сайте и не останавливают бота. Такая реплика останавливает бота только в Telegram Business.
- Instagram и Facebook разрешают отвечать через API в течение 24 часов после сообщения клиента, а WhatsApp требует шаблон после этого срока. Если окно закрыто, сайт покажет причину под сообщением.
- Встроенные подсказки бота написаны на русском (`bot_handle_inbound` в миграции). Тексты вопросов могут быть на любом языке.
- Голосовые, фото и файлы бот не разбирает: на сайте видна отметка о вложении, сам файл не сохраняется.

## Если бот не отвечает

Функция `webhook` пишет диагностику с пометкой `[diag]`. Смотрите её в Supabase → Edge Functions → webhook → Logs сразу после тестового сообщения.

| Что в логах | Причина |
| --- | --- |
| Нет записи о запросе, в Invocations пусто | Платформа не вызывает функцию: webhook не настроен, нет подписки на `messages`, нет роли тестера |
| Запрос со статусом 401 | Включён Verify JWT у `webhook` или неверный App Secret |
| Запрос со статусом 500 | Нет секрета `TOKEN_ENCRYPTION_KEY` или не применены миграции |
| `не совпал с external_id, событие принято по подписи` | Meta прислала другой id аккаунта, канал найден по подписи |
| `событие не сохранено, ignored` | Срок компании истёк, компания приостановлена или канал выключен |

Для Telegram: `https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo` показывает адрес webhook и последнюю ошибку доставки.
